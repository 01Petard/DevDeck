# 开发指南

## 环境

| 工具 | 要求 |
|---|---|
| 系统 | macOS；当前真机验证环境为 macOS 15.7.5 / Apple Silicon |
| Xcode Command Line Tools | `xcode-select -p` 可返回有效目录 |
| Node.js | 24；仓库 `.nvmrc` 指定主版本 |
| pnpm | 11.5.2，与 `packageManager` 一致 |
| Rust | stable，当前锁定依赖要求 Rust ≥1.95 |

版本以 `pnpm-lock.yaml` 和 `src-tauri/Cargo.lock` 为准，不为编译问题随意升级依赖。Xcode CLT 与 Rust 只在开发/构建时需要，安装版不依赖 Node.js 或 Rust 运行环境。

Rust 已安装但终端找不到 `cargo` 时，可在当前终端补充常见路径：

```sh
export PATH="$PATH:$HOME/.cargo/bin:/opt/homebrew/opt/rustup/bin:/usr/local/opt/rustup/bin"
cargo --version
rustc --version
```

`pnpm build:app` 已在自己的进程环境中补充这些路径；手动运行 Cargo 或 `pnpm tauri dev` 仍需要终端 PATH 可用。自定义安装目录请自行加入 PATH。

## 启动开发窗口

```sh
# 使用 nvm 时可先执行 nvm use
pnpm install --frozen-lockfile
pnpm tauri dev
```

原生窗口通过 Rust IPC 获取真实系统数据。`pnpm dev` 只启动 Vite；单独浏览前端页面不能替代原生扫描和进程操作验证。

## 命令与验证

以下命令从仓库根目录运行：

```sh
pnpm test
pnpm build
(cd src-tauri && cargo test --locked && cargo check --locked)
```

- `pnpm test`：前端逻辑测试。
- `pnpm build`：TypeScript/Vue 检查并生成 `dist/`，不生成 App。
- `pnpm build:app`：构建原生 App 和 DMG；Tauri 自动先执行 `pnpm build`。
- `pnpm release`：`pnpm test` 通过后运行 `pnpm build:app`。这是本地构建命令，不上传文件，不创建 GitHub Release，也不代替完整 Release Gate。

Rust 测试默认忽略需要固定端口或显式执行的真机专项。不要盲目运行全部忽略测试；按 [测试与发布](06_测试与发布.md) 和测试说明分别运行，终止试验只能针对自己创建的临时服务。

## 打包

本地自用使用 ad-hoc 签名：

```sh
APPLE_SIGNING_IDENTITY=- pnpm release
```

仅打包、不重复运行前端测试：

```sh
APPLE_SIGNING_IDENTITY=- pnpm build:app
```

同时请求 `app,dmg`，以便保留独立 App。Apple Silicon 的典型产物：

```text
src-tauri/target/release/bundle/macos/DevDock.app
src-tauri/target/release/bundle/dmg/DevDock_<版本>_aarch64.dmg
```

实际名称以 Tauri 输出为准。未配置 Developer ID 和公证凭据时，不要声称完成公众分发验证。构建、Finder 安装、真机回归和签名状态记录要求见 [测试与发布](06_测试与发布.md)。

## 修改版本号

例如升级到 `0.1.2`，同步修改：

| 文件 | 字段 |
|---|---|
| `package.json` | 顶层 `version` |
| `src-tauri/tauri.conf.json` | 顶层 `version` |
| `src-tauri/Cargo.toml` | `[package].version` |

然后在仓库根目录执行：

```sh
# 先同步 Cargo.lock 中本项目的版本，这一步不要加 --locked
(cd src-tauri && cargo check)

# 测试并重新打包
APPLE_SIGNING_IDENTITY=- pnpm release
```

提交时包含这三个文件和更新后的 `src-tauri/Cargo.lock`。检查锁文件差异，单纯修改项目版本不应顺带升级依赖。不要全文替换旧版本号：历史验收记录、校验值、初始规格和依赖版本应保留原值。当前没有自动同步版本的脚本。

## 构建排错

### 删除 target 后没有 App

`src-tauri/target/` 只包含构建产物与缓存，**整个目录都可删除**，没有必须保留的源码或手工文件。运行 `pnpm release` 或 `pnpm build:app` 会重建它；首次全量编译会更慢。

`pnpm build` 只重建前端 `dist/`。如果它成功而 `target/` 尚未生成，这是命令用途不同，不是缺文件。

不要删除 `src-tauri/Cargo.toml`、`Cargo.lock`、`src/`、`icons/`、`build.rs`、Tauri 配置和权限文件。

### cargo metadata 报 No such file or directory

这是 Rust 工具链不在 PATH 或尚未安装，通常还没有进入 Rust 编译。先检查 `cargo --version`；统一打包脚本已补充标准安装路径，自定义安装仍需手动配置。无需恢复旧 `target/`。

### 提示锁文件需要更新

检查三个项目版本号是否一致，再执行不带 `--locked` 的 `cargo check` 同步锁文件。后续验证继续使用 `--locked`，不要删除锁文件来绕过错误。

### 下载 crates 失败

依赖下载缓存位于 Cargo 用户目录，通常为 `~/.cargo/registry/`，与项目 `target/` 不同。缓存不完整时，重新编译需要联网；`--offline` 不能补齐缺失依赖。先检查实际网络错误，不把下载失败误判为源码缺失。

如默认源确实不可用，可仅对本次命令指定镜像，参数会经 `release`、`build:app` 传给 Cargo：

```sh
APPLE_SIGNING_IDENTITY=- pnpm release -- \
  --config 'source.crates-io.replace-with="rsproxy"' \
  --config 'source.rsproxy.registry="sparse+https://rsproxy.cn/index/"' --locked
```

这是可选排错方式，不修改项目或全局下载源；缓存完整时才可另加 `--offline`。

## 收藏配置与恢复

macOS 配置文件：`~/Library/Application Support/top.bugstack.devdock/devdock.json`，根键为 `settings`。仅保存收藏，不保存 PID、扫描快照或健康历史。

配置损坏、版本不支持或保存失败时，界面显示错误，不能静默覆盖原文件。先备份并修复文件，再点击“重新读取”；若决定移走损坏文件，退出应用后处理，重启可初始化新配置。不要同时运行多个实例编辑同一配置；显式保存不承诺断电时原子性。

字段、Unicode 长度与 URL 限制见 [数据契约](03_数据契约与错误码.md)。
